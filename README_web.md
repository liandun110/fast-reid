基于web实现前后端分离，是一步重要改进。

新增功能：显示人物轨迹。为什么需要这个功能？因为，作为一个系统，它展示的最终结果是什么？最终结果是，检索到的行人的行动轨迹。所以这是整个系统的最终输出效果。

放弃功能：人物轨迹仅仅在道路上。为什么需要？这样显然更真实更合理。为什么放弃？1. 实现起来太复杂，涉及到游戏中的路线规划算法。2. 现实意义多大？好像并不是刚需。3. 若增加这项功能，反而导致本系统的泛化性变差，这也是最重要的放弃原因。如果将来在真实地图上运行本系统，哪里弄对应的road.png?且在真实地图这种大尺度上，“人物轨迹仅仅在道路上”的作用就更小了。

放弃功能：每个摄像头检索到的行人，显示在该摄像头旁边，且不能与其他行人重叠。为什么放弃？1. 实现起来太复杂，涉及到不同位置的尝试。就算调整，也有严重相互遮挡。2. 显示意义多大？其实统一显示在界面底部也是一种选择，而且反而更整齐。而且能够定制更丰富功能，比如一个摄像头可以显示多个候选。

cd <项目根目录>
python -m http.server 8000  # 开启前端

# 新建一个bash窗口，开启后端
python app.py
